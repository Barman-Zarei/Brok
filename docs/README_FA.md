# بروک (Brok)

**همراه هوش‌مصنوعیِ دسکتاپ با اولویت فارسی، و یک عامل کدنویسی با دسترسی کنترل‌شده.**

ربات کوچکی که روی دسکتاپ شما زندگی می‌کند، فارسی (و انگلیسی و زبان‌های دیگر) حرف می‌زند و می‌تواند با مجوزهای
صریح و قابل‌ردیابی روی کد شما کار کند — به‌صورت محلی با Ollama یا ابری با Claude / هر API سازگار با OpenAI.

## ✨ چرا بروک

بیشتر دستیارهای کدنویسی هوش‌مصنوعی انگلیسی‌محور و فقط ابری‌اند و دسترسی گسترده‌ای به سیستم شما دارند. بروک روی سه
اصل ساخته شده است:

- **فارسی در اولویت.** رابط راست‌به‌چپ، توضیح فارسی همراه با کد انگلیسی، حالت یادگیری و اشکال‌یاب (debugger) که فارسی
  را می‌فهمد؛ زبان‌های دیگر هم پشتیبانی می‌شوند.
- **کنترل با شماست.** هر کاری که مدل می‌تواند انجام دهد یک «ابزار» با سطح خطر و قاعدهٔ تأیید است. ویرایش‌ها ابتدا
  به‌صورت diff نشان داده می‌شوند؛ حذف، commit و push همیشه تأیید می‌خواهند؛ دستورهای خطرناک پیش از هر پرسشی رد می‌شوند.
  [مدل امنیتی](#-مدل-امنیتی) را ببینید.
- **محلی یا ابری، با شفافیت.** از Ollama روی سیستم خودتان یا از Claude / API سازگار با OpenAI استفاده کنید. رابط
  همیشه نشان می‌دهد با **LOCAL AI** صحبت می‌کنید یا **CLOUD AI**؛ حالت «فقط محلی» هیچ‌وقت به شبکه دست نمی‌زند.

## 🧰 ویژگی‌ها

| بخش | چه چیزی دریافت می‌کنید |
|---|---|
| **همراه دسکتاپ** | آواتار ربات بدون قاب، همیشه روی پنجره‌ها و قابل‌کشیدن، با ۱۳ حالت (آماده، گوش‌دادن، فکر، تایپ، کدنویسی، کار، صحبت، خوشحال، گیج، خطا، موفقیت، خواب، اعلان)؛ بستهٔ آواتار با `pack.json`؛ شخصیت‌های سفارشی. |
| **ارائه‌دهندگان AI** | Claude، Ollama (محلی) و هر API سازگار با OpenAI پشت یک orchestrator واحد با fallback؛ رابط هرگز مستقیم با سرویس‌دهنده صحبت نمی‌کند. |
| **محیط کدنویسی** | مرورگر فایل، ویرایشگر، گفتگوی AI، نمایش diff، ترمینال، مشکلات، git و اطلاعات پروژه. کد را انتخاب کنید ← *توضیح / پیدا کردن باگ / بهینه‌سازی / نوشتن تست / تبدیل به Flutter*. |
| **عامل کدنویسی** | حلقهٔ محدود (سقف برای تعداد گام، زمان، توکن و فراخوانی ابزار)، فهرست پروژه، اشکال‌یاب AI، گزارش سلامت، حالت یادگیری. لغو و مهلت پیش از **هر** فراخوانی ابزار بررسی می‌شود. |
| **عامل ترمینال** | `brok-agent ask · code · fix · debug · learn · health · doctor · privacy · memory` |
| **حافظه و حریم خصوصی** | دیدن / ویرایش / حذف / پاک‌کردن هر چیزی که بروک به یاد می‌سپارد؛ گزارش آنچه ذخیره و ارسال می‌شود؛ کلیدها فقط از متغیر محیطی یا keyring سیستم‌عامل. |
| **قابلیت توسعه** | API پلاگین (ابزار پلاگین هرگز سطح خطر را کم نمی‌کند)، ابزارهای GitHub و جست‌وجوی وب، رابط‌های صوتی (STT/TTS). |
| **از myCat** | یادآورها، دفترچهٔ فعالیت، تایمر تمرکز، اعلان‌های GitHub، یادآور تقویم، شخصیت‌های سفارشی، فروشگاه شخصیت. |

## 🚀 شروع سریع

```bash
pip install .                 # یا: pip install ".[secure,calendar]"
brok                          # اجرای همراه دسکتاپ

# مغز را انتخاب کنید: ابری ...
export ANTHROPIC_API_KEY=...  # (یا OPENAI_API_KEY برای API سازگار با OpenAI)
# ... یا محلی:
ollama pull llama3.1

brok-agent doctor             # بررسی ارائه‌دهندگان و اتصال
brok-agent --project . ask "این پروژه چه کاری انجام می‌دهد؟"
```

به **Python 3.10 یا بالاتر** نیاز است (برای پایتون‌های قدیمی‌تر بخش [شاخه‌ها](#-شاخهها-و-پروفایلهای-ساخت) و
[PYTHON_COMPATIBILITY](PYTHON_COMPATIBILITY.md) را ببینید). از داخل مخزن می‌توانید `run.sh` (لینوکس/مک) یا
`run.bat` (ویندوز) را هم اجرا کنید.

## 🎮 استفاده

**دسکتاپ.** `brok` — با کشیدن (چپ‌کلیک) جابه‌جا کنید، با راست‌کلیک منو (شامل *Coding Workspace…*) را باز کنید.
گزینه‌ها: `--image path/to/char.zip` (شخصیت سفارشی)، `--pos X Y`، `--wait SECONDS`، `--debug`.

**ترمینال.** `brok-agent [--project PROJECT] <command>`:

| فرمان | کاربرد |
|---|---|
| `ask` / `code` / `fix` | متن زبان طبیعی یا فرمان `/command` |
| `debug` | تحلیل خطا یا traceback (متن یا فایل) |
| `learn` | حالت یادگیری |
| `health` | گزارش سلامت پروژه (تقریبی) |
| `doctor` | بررسی ارائه‌دهندگان و اتصال |
| `privacy` | آنچه بروک ذخیره و ارسال می‌کند |
| `memory` | دیدن / افزودن / حذف / پاک‌کردن حافظه |

تنظیمات در `~/.config/brok/` است (پوشهٔ قدیمی `~/.config/mycat` یک‌بار کپی می‌شود و هرگز پاک نمی‌شود).

## 🔒 مدل امنیتی

هر ابزاری که مدل می‌تواند صدا بزند یک `ToolSpec` با سطح خطر است و فقط از مسیر `ToolRegistry.execute` اجرا می‌شود.

| ابزار | خطر | تأیید |
|---|---|---|
| خواندن / فهرست / جست‌وجو، git status / diff / log / branch، بازرسی | LOW | ندارد |
| نوشتن / ساخت / جابه‌جایی، git checkout / stash، اجرای تست / linter / formatter، `fetch_url` | MEDIUM | قابل‌تنظیم |
| `delete_file`، `git_commit`، `github_create_*` | HIGH | الزامی |
| `git_push`، دستورهای sudo / سیستمی / تغییردهندهٔ ریموت | CRITICAL | همیشه (هیچ تنظیمی آن را برنمی‌دارد) |
| دستورهای خطرناک (`rm -rf /`، `mkfs`، نوشتن `dd` روی دیسک، `curl \| sh`، فایل‌های credential، fork bomb…) | BLOCKED | پیش از هر پرسشی رد می‌شود |

- **قفص فضای کار (jail)** — مسیرها با `realpath` حل می‌شوند؛ بیرون‌رفتن از پروژه (`..`، مسیر مطلق، symlink) رد می‌شود و
  پوشهٔ `.git` برای ابزارهای فایل ممنوع است.
- **رازها بیرون می‌مانند** — `.env`، `*.pem`، `*.key` و کلیدهای SSH را عامل نمی‌تواند بخواند یا بنویسد و `git_commit`
  آن‌ها را هرگز stage نمی‌کند.
- **بدون shell** — دستورها به‌صورت فهرست آرگومان اجرا می‌شوند؛ متغیرهای کلید/توکن حذف می‌شوند، مهلت و سقف خروجی دارند و
  دستور در حال اجرا با همهٔ زیرپروسه‌هایش هنگام لغو یا اتمام مهلت کشته می‌شود.
- **محافظ شبکه** — `fetch_url` فقط آدرس‌های عمومی http(s) را می‌پذیرد و هر redirect و نشانی‌ای را که واقعاً به آن وصل
  می‌شود دوباره بررسی می‌کند (محافظت در برابر SSRF و DNS rebinding).
- **پلاگین‌ها نمی‌توانند خطر را کم کنند** — ابزارهایشان حداقل MEDIUM / قابل‌تنظیم‌اند.

**محدودیت‌هایی که باید بدانید:** طبقه‌بندی دستورها الگو‌محور است و با مبهم‌سازی می‌تواند فریب بخورد (به همین دلیل
هر چیز فهرست‌نشده اول می‌پرسد)، هنوز sandbox یا container در سطح سیستم‌عامل وجود ندارد و یافته‌های `health` تقریبی‌اند
و ممیزی امنیتی نیستند. جزئیات: [security.md](security.md).

## 🛡️ حریم خصوصی

بروک نشان می‌دهد چه چیزی ذخیره و ارسال می‌کند (`brok-agent privacy` و پیشخوان حریم خصوصی در رابط)، اجازه می‌دهد حافظه‌اش
را ببینید، ویرایش و حذف کنید، متنی را که شبیه راز باشد ذخیره نمی‌کند و کلید API را هرگز در تنظیمات، لاگ یا حافظه
نمی‌نویسد (`redact()` آن‌ها را پنهان می‌کند). حالت «فقط محلی» همه‌چیز را روی دستگاه شما نگه می‌دارد.
[privacy.md](privacy.md) را ببینید.

## 🧱 معماری

رابط کاربری هرگز مستقیم با API سرویس‌دهنده کار نمی‌کند؛ فقط `AIOrchestrator` این کار را می‌کند. در `ai/`، `agent/`،
`memory` و `config` هیچ import از Qt وجود ندارد، پس هستهٔ برنامه بدون نمایشگر قابل تست است. نقشهٔ ماژول‌ها و قواعد:
[architecture.md](architecture.md) · [ai.md](ai.md) · [coding-agent.md](coding-agent.md) · [plugins.md](plugins.md).

## 🌿 شاخه‌ها و پروفایل‌های ساخت

شاخهٔ `brok-migration` **خط اصلی** است. هر شاخهٔ دیگر یک نسخهٔ متفاوت است که همان کد را به اشتراک می‌گذارد و اصلاح‌ها
از `brok-migration` به آن‌ها merge می‌شوند.

| شاخه | چیست | Python |
|---|---|---|
| `brok-migration` | نسخهٔ اصلی | 3.10+ |
| `PYTHON38` | سازگاری با Python 3.8 | 3.8+ |
| `LEGACY` | سیستم‌عامل‌های قدیمی‌تر، وابستگی‌های قفل‌شده | 3.9 |
| `WIN7` | ویندوز ۷ با Qt 5.15 / PySide2 | 3.8 – 3.10 |
| `LOW-END` | رایانه‌های ضعیف: آواتار حدود ۱۵ فریم بر ثانیه، بدون بررسی به‌روزرسانی | 3.8+ |
| `OFFLINE` | فقط Ollama، بدون AI ابری، بدون بررسی به‌روزرسانی | 3.8+ |
| `LITE` | `pyside6-essentials` به‌جای PySide6 کامل (نصب کوچک‌تر) | 3.8+ |
| `NO_GPU` | رندر نرم‌افزاری Qt | 3.8+ |
| `EXPERIMENTAL` | کار ناپایدار، لاگ DEBUG | 3.8+ |
| `ANDROID` | APK با `pyside6-android-deploy` (آزمایشی) | 3.10+ |
| `IOS` | پروژهٔ Xcode با ابزار Qt (آزمایشی) | 3.10+ |

پروفایل اجرا را هر جا می‌شود با `BROK_PROFILE=<name>` عوض کرد (`standard`، `lite`، `low-end`، `no-gpu`، `offline`،
`experimental`).

**پشتیبانی پلتفرم:** لینوکس **اصلی** است (توسعه و تست اینجا انجام شده). ویندوز ۱۰+ و macOS باید کار کنند ولی روی دستگاه
واقعی بررسی نشده‌اند. شاخهٔ `WIN7` فقط روی لینوکس تست شده، **نه روی خود ویندوز ۷**؛ `ANDROID` و `IOS` فقط نقطهٔ ورود دارند.

## 🧪 توسعه

```bash
pip install -e ".[dev]"
QT_QPA_PLATFORM=offscreen pytest -q      # بیش از ۵۵۰ تست، بدون نمایشگر
ruff check . && ruff format --check .    # lint / قالب‌بندی
```

CI ماتریس تست را روی چند نسخهٔ Python و `mypy --strict` را روی ماژول‌های هسته اجرا می‌کند
([ci.yml](../.github/workflows/ci.yml)). بیشتر: [CONTRIBUTING.md](../CONTRIBUTING.md) و
[development.md](development.md). تغییرات نسخه‌ها: [CHANGELOG.md](../CHANGELOG.md).

**وضعیت پروژه: آلفا (۰٫۲٫۰).** هسته — ارائه‌دهندگان، ابزارها، مجوزها، حلقهٔ عامل، حافظه، فهرست پروژه، آواتار، محیط کدنویسی،
میانبرها — با تست خودکار پوشش داده شده (بدون نمایشگر، روی لینوکس؛ Python 3.8 تا 3.12). **توسط نویسندگان بررسی نشده:**
فراخوانی واقعی Claude / OpenAI / Ollama / GitHub با کلید واقعی، ساخت ویندوز و macOS، نمایشگر فیزیکی و تبدیل گفتار به متن
با میکروفون. مشکلات را در [issue tracker](https://github.com/Barman-Zarei/Brok/issues) گزارش کنید.
